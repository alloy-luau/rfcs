- Feature: a short name, the file's own
- Start date: YYYY-MM-DD
- RFC PR: the pull request's number
- Tracking issue: the issue that follows the work

# Summary

One paragraph. What changes, in a sentence a user reads.

# Motivation

The problem this solves, in the words of someone who has it. Name the
code that is hard to write today, and what a reader of that code gets
wrong. An example of the pain earns more than a paragraph about it.

# The design

What the user writes, and what it means. Show the syntax, every form of
it, with a worked example that compiles. Say what the compiler emits,
since Alloy promises the emit adds no line. Name the errors a wrong
form draws, in the words the compiler uses.

# What it costs

Every proposal costs something. Name it: a word the language reserves,
a shape that no longer parses, a rule the reader has to hold, a file
the build now writes. Say what a project with the old form does.

# The alternatives

The designs that were weighed and set aside, and why this one won. A
proposal with no alternatives has not been thought through.

# Open questions

What the discussion has to settle before the work starts.
