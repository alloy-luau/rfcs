# Feature name

## Summary

One paragraph. What changes, in a sentence a user reads.

## Motivation

The problem this solves, in the words of someone who has it. Name the
code that is hard to write today, and what a reader of that code gets
wrong. An example of the pain earns more than a paragraph about it.

## Design

The bulk of the proposal. What the user writes, and what it means, in
enough detail for someone who knows the language to build it. Show every
form of the syntax with an example that compiles.

Say what the compiler emits. Alloy puts the emit on the source's own
lines, so a proposal says how that holds.

Name the errors a wrong form draws, in the words the compiler uses, and
say what the language server does with the feature: what completes,
what a hover reads, and where an error lands.

## Drawbacks

Why not do this. Name the cost: a word the language reserves, a shape
that stops parsing, a rule the reader has to hold, a file the build now
writes. Say what a project written against the old form does.

## Alternatives

The designs that were weighed and set aside, and why this one won. Say
what happens if nothing is done.

## Prior Art

- Does another language have this? What does it look like there, and
  how does that compare? What does Alloy have that changes the answer?
- What comes with the feature elsewhere that this proposal leaves out?
- Does Alloy already have something near it? Does this name it the same
  way, read the same way, and behave the same way?
